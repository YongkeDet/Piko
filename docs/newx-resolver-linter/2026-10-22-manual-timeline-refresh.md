# Existing timelines refresh only on pull-to-refresh

- Requested behavior: preserve first loading and downward pagination, but allow only a manual pull to refresh an existing timeline. The user explicitly confirmed that first loading and pagination should remain enabled.
- Target package/version: `com.twitter.android`, `12.35.0-prod.01` production. Input APKM is the original file in the task workspace. Piko source is pinned to `11ea728b9e0a907b2162b79445368cbcef21e783`; previous behavior is preserved in release `X.26.02`.
- APK contract: the exact input DEX declares request enum constants `PULL_TO_REFRESH`, `OLDER_THAN`, `GAP`, `AUTO_REFRESH`, `VIEWPORT_AWARE_AUTO_REFRESH`, and `NEWER_THAN`. The observed obfuscated owner is reconnaissance evidence only; production hooks derive its owner from the existing URT fingerprint and require it to extend `java.lang.Enum` with the manual/paging constants present.
- Existing gaps: the repository gate only suppressed `AUTO_REFRESH` with a null cursor, and explicitly allowed refreshes following a post deep link or For You filter change. The event handler had the same special allowances. The viewport-aware and newer-content paths could bypass the repository gate.
- Change: retain the existing setting read, scoped timeline matching, and initial position restoration. Check all request cursors through a stable extension policy (`Enum`, `List`): nonempty timelines allow `PULL_TO_REFRESH`, `OLDER_THAN`, and `GAP`; other request types, including unknown future refresh types, are blocked. Empty page containers are initial loads and remain allowed. Remove the deep-link/filter exemptions for populated automatic-refresh events. The topic selector also defers its clear-and-refresh bridge while the toggle is enabled, so clearing the old list cannot masquerade as a first load. It saves selection immediately and applies it on the next pull.
- Tests: the runtime policy is exercised over every observed request type, an unknown future request, null requests, populated pages, and null/empty/nested-empty initial page containers. Enum order is deliberately shuffled. Cloud compilation runs the focused Android unit test before creating the MPP. The patch keeps the existing resolver rather than matching an obfuscated owner.
- Verification limits: successful MPP compilation and policy tests do not prove APK mutation or phone behavior. The cloud builder does not currently have the original APKM as an input, and no device was controlled. Apply the new subscribed bundle to the original `12.35.0-prod.01` APKM and check foreground return, manual pull, and downward pagination on the phone.
- Rollback: `X.26.02` remains the previous release; switch the setting off to restore the native request flow without replacing the package.
